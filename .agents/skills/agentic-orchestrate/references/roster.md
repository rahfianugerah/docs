# Roster

| Agent | Tier | Launch it to |
| :- | :- | :- |
| `advisor` | deep | Launch when a build or fast agent asks for a second opinion: before a hard-to-reverse decision, on an ambiguous requirement, after the same fix failed twice, or before crossing a boundary. |
| `architect` | deep | Launch when a task adds or changes a module boundary, a public API, a data model, or the directory structure, before any build agent starts on it. |
| `formal-verifier` | deep | Optional. Launch only for a critical state machine, concurrent protocol, or algorithm, where a bug costs the most and tests reach the least, to check one property with a TLA+ model or a Lean proof. |
| `harness-improver` | deep | Launch when a real run shows the harness falling short, such as a misrouted task, a repeated mistake, an ignored rule, wasted tokens, or a fix loop that hit three rounds, to propose, probe, and keep or reject one change on evidence. |
| `orchestrator` | deep | The main session on every request. Splits the work into tasks, routes each to the cheapest agent that can do it, merges the results, and commits locally at a close. Never launched as a subagent. |
| `planner` | deep | Turns a spec into ordered tasks, each with its files, risks, dependencies, and agent, and keeps a project's docs/PRD.md, docs/SRS.md, and docs/PLAN.md. Launch it at intake after the system-analyst, after the security design check, at a release, and for the session-start status. |
| `research-agent` | deep | Launch when a task depends on something unknown: how a library or an API behaves, what its documentation says, what prior art exists, or where and how the codebase already does something. |
| `security-reviewer` | deep | Runs the security design check of a planned change, reviews the diff of every built change, audits the full codebase at a release, and keeps the content of a project's SECURITY.md. Launch it after the plan, on every built change alongside the verifier and the slop-reviewer, at a close, and at a release. |
| `slop-reviewer` | deep | Reviews a diff against rules/codes.rules.md for comments that restate code, quick-fix patches, dead code, over-abstraction, invented APIs, swallowed errors, and boundary violations, and returns Pass or Fail. Launch it on every built change, after a fix to one of its findings, and at a release. |
| `system-analyst` | deep | Turns a request into requirements, edge cases, data flows, and acceptance criteria, analyses the solution for a security finding, and writes the Needs Decision report. Launch it at intake, on every security finding, and after a third failed fix round or when two agents disagree. |
| `verifier` | deep | Independently checks a change against its requirements by running lint, types, tests, and the application, and returns Pass or Fail with JSON evidence. Launch it on every built change, after every fix, at a wave close for the full suite, and at a release for the full regression. |
| `backend-engineer` | build | Builds exactly one backend task on FastAPI, SQLAlchemy, and PostgreSQL, or fixes the listed items of a Fail report, and only builds, with no tests and no test runs. Launch one per independent backend task, up to three in parallel. |
| `devops-engineer` | build | Launch for one infrastructure task: a Dockerfile, a cloudbuild.yaml, a Cloud Run service or job, a deploy runbook, a scheduled automation, or a trigger that starts work unattended. |
| `frontend-engineer` | build | Builds exactly one frontend task on React, Vite, HeroUI, and TanStack Query against the API contract, or fixes the listed items of a Fail report, and only builds, with no tests and no browser checks. Launch one per independent frontend task, up to three in parallel. |
| `statechart-modeler` | build | Launch before building, or while debugging, a UI or async flow with complex state, such as a wizard, a checkout, an upload with retry, or a connection that drops, to draw its statechart and list the states nothing handles. |
| `test-designer` | build | Picks the kinds of test a change needs and writes them: unit, property-based, contract, integration, regression, end to end, and performance. Launch it once a task is built, and before a bug or security fix for the failing test the fix must turn green. |
| `chore-agent` | fast | Does mechanical work that needs no decision: formatting, lint autofixes, renames, regenerating files, and syncing documents at a close, such as the Done log in docs/PLAN.md or a README. Launch it for any task a command or a find-and-replace can finish. |
